## SoC Verify v0.5.0

本版本是 SoC Verify 的重大升级——完成 AI 引擎从 oh-my-pi (omp) 到 pi coding agent SDK 的全面迁移，pi 成为唯一 AI 引擎运行时。迁移涵盖引擎中立契约、runner 交互链路、Host Tools/MCP/审批信任闭环、子代理父子工作流、会话恢复、技能治理、依赖治理与打包链等 9 个 issue 闭环。同时带来设计视图框图自动布局、Token 监控图表增强、子代理会话支持完善等多项功能增强。

## Highlights

- **Pi 引擎全面迁移（issue 02-10）**：从可行性验证到引擎中立契约建立、runner 核心链路、Host Tools/MCP/审批信任闭环、子代理父子工作流、模型认证对齐、会话恢复与 cwd 安全边界、外部 session 接管与旧 omp 清理、技能来源治理、构建链移除与依赖治理，共 9 个 issue 闭环，pi 成为唯一 AI 引擎运行时
- **引擎中立 Agent 契约（issue 02）**：建立 IAgentClient 契约（init/prompt/steer/abort/setModel/compact/destroy）、AgentEvent 判别联合与 AgentClientFactory 工厂缝，SessionManager 依赖注入，持久化层 engine/engineSessionId/cwd 中立命名
- **Pi Runner 核心交互链路（issue 03）**：新增 runner-pi（ELECTRON_RUN_AS_NODE=1 复用 Electron 内置 Node），实现 ready 握手与全链路命令；pi 原生事件经 event-normalizer 归一化为 Agent Event Contract，渲染端不感知 pi 事件形状
- **Host Tools/MCP/审批信任闭环（issue 04）**：runner-pi 新增工具分级审批逻辑、MCP 配置解析与信任分区、审批门内联扩展与 pi-mcp-adapter 装配；host 侧新增 TrustStore 持久化信任记录；TrustCard UI 组件（yolo 不绕过信任确认）
- **子代理父子工作流（issue 05）**：装配 pi-subagents@0.66.0，事件桥订阅异步生命周期；父子关系追踪（parentSessionId/ownerRunId/runDir）；取消传播双通道（引擎 abort signal + host cancelSubagent 命令）；审批继承与 Token 归属旁路写入
- **模型/认证/上下文能力对齐（issue 06）**：init 接线 thinkingLevel/contextWindow/systemPrompt；新增 setThinkingLevel/setToolFilter/listAgentTools/getMessages/getState/getSystemPrompt 命令；context_usage 推送在 message_end/agent_end/compaction 边界触发
- **原生会话恢复与 cwd 安全边界（issue 07）**：原生 session 优先恢复（SessionManager.list(cwd) 按 canonical bucket 定位），缺失/损坏时降级为 transcript 重建；rebindCwd 显式重绑定；isCwdAccessible 门控防止不可访问路径创建运行时会话
- **外部 Session 接管与统一删除（issue 08）**：external-pi-sessions 只读扫描 + 去重 + adopt 显式接管（信任边界校验）；session-deletion 统一物理删除（index/transcript/native/artifacts 分步报告）；omp-legacy-cleanup 精确匹配 header id 清理旧会话；崩溃语义（ready 后子进程退出 → 合成 error 事件）
- **技能来源与信任治理（issue 09）**：canonical 来源（项目 .pi/skills、用户 ~/.pi/agent/skills），旧 .omp/skills 只读兼容一个版本周期（移除期限 v0.6.0）；同名解析 first-wins；resolveSkillLoadPaths 为 pi 引擎下发 InitConfig.skillPaths
- **构建链移除与依赖治理（issue 10）**：删除 engine/oh-my-pi submodule 与旧构建链；pi 依赖移至 devDependencies，运行时载荷由 resources/runner-deps 经 npm ci 安装并 prune（实测 −101.8 MB）；载荷门禁接入打包链（30 MB 阈值，超限需显式 ack）
- **设计视图框图自动布局**：使用 ELK Worker 实现异步布局并支持取消；连线绕行算法优化（多障碍正确避让）；新增架构模式（默认隐藏普通信号仅展示时钟/复位/总线）；连线语义分类与样式区分（选中高亮与流动动画）
- **子代理会话支持完善**：新增 AssistantMessageContent 组件统一渲染助手消息；新增 subagent_stream 事件类型与流式消息渲染；SubagentBody 组件替代 JSON 兜底展示；前台/异步子代理进度流式更新与防抖
- **Pi-web-access 网络工具**：新增 fetch_content/get_search_content/source_check 三类网络工具与富展示卡片
- **rpiv-todo 扩展支持**：新增 @juicesharp/rpiv-todo 依赖，实现 rpiv 格式待办数据解析与全量快照展示
- **Token 趋势 sparkline 增强**：Catmull-Rom 算法生成平滑贝塞尔曲线；面积渐变填充；鼠标悬停显示明细 tooltip（日期、token 数量、费用）

## Fixes

- 修复审批模式（approval mode）未传播到恢复/模型切换会话的问题——持久化 approvalMode 到 PersistedSession 和运行时 SessionEntry，create/restore/rebindCwd/setModel-swap 复用，渲染端恢复时回退到持久化值 → localStorage → yolo
- 修复子代理会话模型继承工厂的安装逻辑——无 modelsPath 时仍可正常创建会话
- 修复子会话进度与 token 统计逻辑——新增 normalizeForegroundProgressFrames 与 normalizeAsyncStatusProgressFrames
- 修复会话消息 store 中 assignment 字段未正确赋值的问题
- 修复误标限流错误导致网关误判配额耗尽的问题——新增误标限流错误改写逻辑

## Refactor

- 知识库从多 tab 工作台迁移到独立视图路由，移除 kb 相关工作台类型
- 子代理工具渲染与管理逻辑重构——移除旧 task 工具子代理支持，统一为 pi-subagents 工作流
- 错误展示逻辑优化——延迟错误卡片到回合结束时渲染，新增 pendingError 字段暂存 LLM 错误文本
- 模型条目生成逻辑适配 pi-ai 的模型 schema 要求，移除 omp-era 的 thinking 声明
- 覆盖率报告解析与测试全面重构——视图聚焦行覆盖率，迁移 legacy IMC 和 vcs-urg 配置，优化数据导入流程
- 回归引用增强——ResolvedGroupRef 类型添加 reason 字段描述不可读文件原因，实现不可读引用路径复制功能
