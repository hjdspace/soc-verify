仿真 Debug 快捷按钮 — UI 方案对比

移植 runsim_r3p0 执行日志页的五个快捷按钮：打开 Verdi · 打开 Verisium · 编译日志 · 仿真日志 · 反汇编文件。
日志/反汇编类按钮支持「内置编辑器 / gvim」两种打开方式；Verdi 按钮自动检测 VCS（run_verdi_vcs）与 XRUN（run_verdi comp_load）。
仿真页底部悬浮 Dock（毛玻璃）
方案 A — 悬浮 Debug Dock 你的原始想法
仿真页存在运行记录时，底部中央悬浮工具条；目标 = 运行列表选中项（可点击切换）；内置 / gvim 打开方式全局切换。
  • 一眼可见，随时可达，不占固定空间
  • 目标用例可切换（含已完成 run）
  • 离开仿真页即不可见，debug 时需切回
  • 悬浮条可能与底栏/命令栏视觉重叠

终端工具栏（Python 原版对应位置）
方案 B — 终端工具栏集成 推荐
扩展 SimControlToolbar（终端仿真 tab 顶部）：debug 按钮作用于本 tab 的仿真——与 Python 版「按钮作用于当前日志 tab」语义完全一致。
  • 看仿真输出时按钮就在手边（debug 主场景）
  • 目标语义零歧义：按钮属于哪个 run 一目了然
  • 日志按钮分裂式设计：点击=内置，箭头=gvim
  • 工具栏变宽，仅紧凑图标承载

运行列表行 hover 图标组
方案 C — 运行行内按钮
运行列表每行 hover 时展开 debug 图标组 + ⋮ 菜单；作用于所在行，天然支持对任意历史 run 直接 debug。
  • 每个 run 都有入口，粒度最细
  • 不增加常驻 UI，界面最克制
  • 入口隐藏较深（需 hover 发现）
  • 行内空间有限，需菜单承载打开方式

建议组合：方案 B（主）+ 方案 A（可选增强）。B 与 Python 版心智模型一致、上下文最明确； A 满足你「仿真页一眼可见」的诉求，两者共享同一套后端（用例目录解析 + 打开动作），实现成本增量很小。 方案 C 的「对任意历史 run debug」能力可通过 A 的目标切换下拉覆盖。
