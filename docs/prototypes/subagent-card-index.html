Subagent Card · UI 方案对比

当 LLM 通过 task 工具派遣 subagent 时，用专用卡片替换默认 TaskBody，并支持实时流式输出。三个方案均含动画模拟（▶ 重播 / ⏭ 跳到最终态），底部悬浮条可互相切换。
omp 派遣机制（数据源已确认）：task 工具输入 tasks[]（id / description / role / assignment / isolated）；omp 通过三类 RPC 帧流式推送 — subagent_lifecycle（started/completed/failed/aborted）、 subagent_progress（currentTool / recentOutput / toolCount / tokens，已节流合并）、 subagent_event（完整子会话事件流，含 message_update 流式文本）。 帧携带 parentToolCallId 可直接关联到对应 tool card。当前渲染端未消费这三类帧。
A
泳道式并行监控
每个 subagent 一条泳道，实时显示 currentTool / tokens / 工具数；汇总进度条置顶；点击泳道展开内联流式日志。类似 CI pipeline 视图。
并行监控一目了然 密度高 流式文本空间受限
B
嵌套手风琴迷你会话
每个 subagent 一个折叠区块，折叠时显示 lastIntent 单行；展开后是迷你会话 — 流式 assistant 文本（打字机效果）+ 工具调用行 + 结果块。
可见推理过程 类 Cursor 体验 展开时占用聊天流高度
C
聚合磁贴 + 抽屉详情
卡片本体极简：磁贴网格（状态点 + currentTool + token sparkline）；点击磁贴右侧抽屉弹出完整实时日志流。聊天流占用最小。
占用空间最小 详情全屏流 多一步点击
实现提示：数据通路为 omp stdout 三类帧 → 主进程 agent-client 识别 → webContents.send + eventBridge（tRPC subscription 不可用）→ 渲染端 session store 按 parentToolCallId 聚合到 tool message → 新 SubagentCard 组件替换 TaskBody。 需向 omp 发送 set_subagent_subscription 开启事件订阅。
