桌面 Shell 重设计 · 3 种方向

当前 UI 是经典 VSCode 式 IDE 布局（TitleBar + 文件树左栏 + 多 Tab 中区 + AI 聊天右栏 + 底部终端）。以下 3 个原型各自探索一个真正不同的设计轴，点击卡片打开可交互原型。

当前痛点分析：① 信息架构以「文件树」为中心，但产品定位是验证管理平台，用户核心关注的是「验证状态与进度」；② TitleBar 右侧堆叠 7+ 个功能按钮，视觉拥挤；③ AI 聊天作为右栏附属，与「AI Agent 驱动」的产品定位不匹配；④ 状态信息（运行徽章、任务面板、仿真结果）散落多处。
A · Mission Control 轴线：状态导向
打开即见全局仪表盘：覆盖率、回归进度、运行中仿真流、AI Agent 活动。文件树降级为可呼出抽屉，左侧为窄图标导航。
胜在验证经理/开工第一眼；大屏监控 8 小时回归
代价写代码/编辑文件路径变深，需抽屉跳转
B · AI Workbench 轴线：对话驱动
AI 会话即主界面。代码、仿真结果、覆盖率以嵌入式工件出现在对话流中；左侧会话与上下文，右侧 Agent 计划/子代理/审批。暖纸白 + 紫梅。
胜在与「AI Agent 驱动」定位一致；审批流天然融入
代价并行浏览多个文件/表格的效率低于 IDE 式布局
C · Dense Pro 轴线：密度专业
琥珀磷光终端美学：菜单栏 + 等宽字体主导 + 多面板并列（文件树/编辑器/日志/覆盖率表格）。键盘驱动，参照 Verdi/JasperGold 专业密度。
胜在资深验证工程师日常深度工作；信息密度最高
代价学习成本高；AI 能力视觉上退居次要
已选方向 → A v2 · Mission Control 细化版
在方案 A 基础上细化：总览 / 仿真 / 覆盖率 / 回归 四大视图 + 里程碑进度、通知中心、命令面板（Ctrl+K）、文件树与 AI 会话抽屉、骨架屏 / 空状态、状态栏 —— 全部可交互。
三种方向互斥但可组合：例如以 A 的仪表盘作为启动页 + B 的对话工作台作为主工作流。选定方向后可再运行一轮 riff，在其基础上细化。
原型均为静态自包含 HTML，含基础交互（tab 切换、树展开、工件折叠）。数据为演示用真实语境内容。
